# client の回し方

作る範囲を開発の外にいる依頼主の答えが決める場合の回し方を、[team](team.md) との差分だけで示す。
題材は同じ会議室予約アプリで、総務部から受けた案件とする。導入した先で守る規約は
`units/flow-client/docs/ops/client.md` にある。

team では作業を止めるのは実装である。依頼主がいると、作業を止めるのは答えになり、答えは開発側の
都合では早まらない。そこで、**答えを待たずに仮の案で作り、何を仮に置いたかを残す**。

## 足すもの

- **問いの Issue**: 依頼主に聞くことを、`question` ラベルの Issue として立てる。1つの問いに1つの Issue
- **仮定**: 作業の Issue の `仮定` 欄に、仮に置いた案と問いの Issue の番号を書く
- skill `client-next`: 問いを立てる、届いた答えを回収する、次に着手する Issue を選ぶ

## 1つの問いの流れ

```mermaid
flowchart TD
    G[決まっていない点] --> Q["問い #13（question）"]
    G --> I["#12 仮定：15分単位"]
    Q -.->|渡す| CL(["👤 依頼主"])
    I ==>|team の1周| M[マージ]
    CL -.->|答え| R[問いに写して閉じる]
    R --> X{仮の案と同じか}
    X -->|同じ| N[何もしない]
    X -->|違う| J["合わせる Issue #20"]
```

点線は開発の外とのやりとりを表す。作業の Issue（太線）は答えを待たずに進む。

### 1. 問いを立て、仮の案で起票する

相談者は #12「同じ部屋で時間帯が重なる予約を拒否する」を起票するときに、要件定義書に時間の刻みが
書かれていないことに気づく。刻みが決まらないと重なりの判定の丸め方が決まらないが、決めるのは依頼主である。
相談者は `client-next` で問いの Issue #13 を立てる。

```text
> /client-next 予約の時間の刻みを総務部に聞きたい
```

```markdown
問い: 予約の開始と終了の時刻は15分刻みに限りますか
選択肢: 15分刻み / 5分刻み / 1分単位（自由）
仮の案: 15分刻み。現在の紙の予約表が15分の升目で、重なりの判定も単純になるため
掛かる Issue: #12
期限: 11/14。予約画面の作成（#15）に着手する時点で、入力欄の刻みが決まっている必要がある
```

#12 の `仮定` には、仮の案と問いの番号を書く。

```markdown
仮定: 開始と終了は15分刻みに限り、それ以外は 422 で拒否する（#13 の答え待ち）
```

#12 は答えを待たずに裁可を受け、team と同じ1周でマージまで進む。

### 2. 問いを渡し、答えを写す

user は #13 の本文を、総務部の担当者へメールや打ち合わせで渡す。答えを受け取った人は、答えをそのまま
#13 のコメントに写して閉じる。**答えの正本は問いの Issue に置く**。メールの中にしか無い答えは、次に作業する
人には見えない。

```text
$ gh issue comment 13 --body "総務部より（11/10 メール）: 5分刻みにしてほしい。15分では打ち合わせの前後の移動時間を取りにくい。"
$ gh issue close 13
```

### 3. 答えを回収する

相談者は `client-next` を呼び、閉じた問いの答えと仮の案を突き合わせる。今回は仮の案（15分刻み）と答え
（5分刻み）が違うので、掛かる Issue を次のように扱う。

- 閉じた #12 は開き直さず、答えに合わせる #20 を `draft` で起票する。開き直すと、何を裁可して作ったかが
  後から読めなくなる
- まだ着手していない #15 は、本文の刻みを直して `draft` を付け直し、裁可を受け直す

答えが仮の案と同じなら、作業の Issue にその旨をコメントするだけで済む。

## 次に着手するものを選ぶ

`client-next` は、答え待ちの問いに掛かっていない Issue を先に並べる。掛かっているものにも着手してよいが、
どの問いの答えでやり直しになりうるかを添える。たとえば取り消しの期限を聞く #17 が開いていれば、
#17 に掛かる #18（予約の取り消しを開始前に限る）は後ろに並び、「#17 の答えでやり直しになりうる」と添えられる。

## 依頼主に見せる現在地

依頼主が知りたいのは、何ができていて、何が自分の答え待ちかである。どちらも一覧で答えられる。

- できたもの: 閉じた作業の Issue のうち、開いている問いに掛かっていないもの
- 答え待ち: 開いている `question` の Issue と、それぞれに掛かっている作業の Issue

#18 が閉じても、#17 が開いているうちは「できたもの」に入らない。
