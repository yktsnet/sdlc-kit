# grasp

`grasp` skill が、main のあるコミットまでのアプリの全体像を、1本の概要資料にまとめ、呼ぶたびに作り込む。

**この文書と `.claude/skills/grasp/` は、`sdlc-kit` から取り込んだものである。** 取り込んだ
時点でこのリポの持ち物になった。以降はここを直す。

## 何のためにあるか

AI と進める実装は文書より速く進む。正本の文書は機能ごとに詳しくなっていくが、アプリが誰に
どう使われ、データがどの段階を通り、どの機能がどうつながっているかは、どれを読んでも見えてこない。
アプリに初めて触る担当者は、どこから読めばよいかで迷う。

この単位はアプリ全体を1本の概要資料にまとめ、初見で分かる形に保つ。概要資料は正本への案内で、骨組みと
読む文書だけを書く。実装が進むたびに呼び、前回反映したコミットから古くなったところと、新しく書けるように
なったところを埋める。始めたばかりのリポには薄い概要資料が、育ったリポには厚い概要資料ができる。

## walkthrough との分け方

`walkthrough` も取り込んでいるなら、扱う範囲で分ける。読み手はどちらもアプリに初めて触る担当者で、
概要資料で全体をつかんでから、walkthrough で機能を確かめる順に読む。

| | grasp | walkthrough |
|---|---|---|
| 扱う範囲 | アプリ全体。機能をまたぐつながり | 中核の機能1本の中 |
| 書くもの | 使われ方、処理の段階、規則の骨組み、外とのつながり、到達点 | 判断の規則と、手で確かめる例 |
| 本数 | 1本を作り込む | 中核の機能ごとに1本 |
| 呼ぶとき | 実装が進んで概要資料が古くなったとき | 中核の機能を作り終えたとき |

1つの機能の中の判断を walkthrough に書いたら、概要資料からはその walkthrough へ案内する。

## 取り込んだあとにやること

1. 欄を埋める。欄は `.claude/skills/grasp/SKILL.md` の「このリポでの置き場」の節と、手順のコマンドにある。表の欄名はどこに出てきても実値に置き換える。
   当てはまる置き場が無い欄（読み手の記録を残していないなど）は、SKILL.md の行ごと消す。出力に見本が要らないなら、「このリポでの置き場」の出力の見本の行と一緒に「出力の見本」の節も消す

   | 欄 | 何を書くか |
   |---|---|
   | `<概要資料の置き場>` | `overview.md` と見本を置くディレクトリ |
   | `<正本の文書>` | 仕様・API・画面・完成表など、概要資料が案内する正本の文書のパス |
   | `<設計判断の置き場>` | なぜそう作ったかを書いた文書（README の「設計判断」の節、`JUDGE.md` など） |
   | `<計画の置き場>` | まだ作っていないものの予定を書いた文書（`PLAN.md`、Issue の一覧など） |
   | `<変更の説明の置き場>` | マージした変更の意図を読む場所（PR 本文、Issue の完了条件、作業記録など） |
   | `<読み手の記録>` | 読み手がつまずいたところを残した文書（学習ノートなど） |
   | `<出力を出す手順>` | 画面を立ち上げる、帳票やファイルを出力する手順 |
   | `<入口の文書>` | 初めて読む人が最初に開く文書（README など） |
   | `<文書だけの変更を出す作業フロー>` | 文書だけの変更を出すブランチの種類（`day/` など） |
2. `CLAUDE.md` の skill 一覧に `/grasp` を足す
3. `/grasp` を1回呼び、骨組みを作る

埋め残しは表の欄名で探す。表の行そのものは除く。何も出なければ埋め終わっている。

```bash
grep -rnF -f <(sed -nE 's/^ *\| `(<[^>]+>)` \|.*/\1/p' docs/ops/*.md | sort -u) CLAUDE.md .claude docs/ops | grep -vE '^[^:]+:[0-9]+: *\| `<'
```

## 使い方

実装がある程度進んだら `/grasp` を呼ぶ。定期に回してもよい。書き終えた概要資料は、初めて読む担当者の
目で読み、迷ったところを伝えて直させてから出す。
