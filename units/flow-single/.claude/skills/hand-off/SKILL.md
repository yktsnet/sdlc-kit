---
name: hand-off
description: work で実装した作業ブランチを、完了条件を証拠で裏付けたうえで push し PR を立てる。マージはしない（user が押す）。
---

単発フローの引き渡し段。**証拠の無い完了を書かない。** 実装したという記憶も、コードがそこにあるという事実も証拠にならない。何を実行すれば真だと言えるかを先に決め、実際に実行する。

1. `git log main..HEAD` で、`work` が残した完了条件と保証を読み出す
2. 完了条件を1つずつ、**実際に実行して**裏付ける
   - 実行したコマンドとその出力を控える。出力を要約せず、判定に必要な行はそのまま残す
   - 実行者側で完結しない確認（デプロイ後の動作・ブラウザ目視・実機確認）は、裏付けずに `## 検証手順` へ回す。ここで「確認済み」と書かない
   - 裏付けられなかった完了条件があれば、PR を立てずに報告して止まる
3. PR 本文を組み立てる

   ```
   ## 変更内容
   {何をしたか}

   ## 完了条件
   - {宣言した条件}

   ## 証拠
   {完了条件ごとに、実行したコマンドと出力の該当部分}

   ## 保証
   {保証の各項目 → それを固定したテスト（ファイル・テスト名）。伴わない場合は `なし（理由）`}

   ## 検証手順
   {user が実施する確認。実行者側で完結しないものだけ。なければ省略}
   ```

4. 作業ブランチを push し、3 の本文で PR を作成する
5. **マージはしない。** PR の URL と、user が実施する検証手順を報告して終了する

`main` への直接 push とマージは `.claude/settings.json` の deny とフックが遮断する。自分の変更を自分で公開に載せない。
