# walkthrough

## 目的

**中核の機能1本を、入口から出口まで追える解説書にする。** 読む人は、まず資料を読み、必要なら
資料を前提に AI へ質問し、理解を深めたくなったときに手で確かめ、実際に動かす。資料はその各段の
足場になるように書く。理由は `docs/ops/walkthrough.md` の「何のためにあるか」にある。

この skill は書くところまでを持つ。どの段まで進むか、いつ進むかは読む人が決める。

## 作るか、直すか

中核の機能にだけ作る。中核かどうかは、なぜこの機能を丁寧に説明するのかを1行で言えるかで決める。
言えないなら作らない。

既存の資料が扱う機能に、規則や項目が足されただけなら、新しく作らずにその資料を直す。

どちらにあたるかを user に示してから書き始める。

## 資料が持つもの

**読む人が、実装を信じずに、手元で同じ結果を再現できること**を基準に置く。読む人には、数か月後の
作った本人も含む。次の要素は、その基準から出てくる。章の名前と順は機能に合わせてよい。機能によって
重みも変わる。計算する機能なら判断の規則と手計算が中心になり、状態を変える機能なら遷移が、外へ渡す
機能なら項目の対応が中心になる。

書き出しは `reference/walkthrough-template.md` を使う。すでに書いた資料があるなら、型よりもそちらに
揃える。

- **何を受け取り、何を出すか。** 最初の数行で機能の輪郭が分からないと、先を読む理由が無い。
  出力の見た目を1つ添える。画面・帳票なら画像、CLI・API・ライブラリなら実際の出力をそのまま貼る
- **なぜこの機能か。** 全体のうちの一部分を丁寧に説明する意味は、それが中核であることにある。
  似た役割のもの（試作や旧実装）があれば、何が違うのかもここで言う
- **入力と、出力までの経路。** 再現の出発点になる。対象にならない入力も、ならない理由と一緒に書く。
  何が除かれるかが分かって初めて、残ったものを信じられる
- **どう判断しているか。** 計算の規則、状態が変わる条件、項目の対応づけ。機能の正しさはここで決まる。
  出力のどこに、その判断の根拠が現れるかも書く。根拠を辿れないなら、正しいと言う手がかりが無い
- **手で確かめる例。** 具体的な入力を1〜2件選び、判断の規則を当てて出力に至るまでを途中まで書く。
  出力のどこで同じものが見えるかを添える。ここが資料の中心になる。例は実際に動かした結果と
  突き合わせてから書く。確かめていない例は、読む人を誤った理解へ連れていく。読む人が資料を前提に
  AI へ質問するときも、確かめた例が話の出発点になる
- **自分で動かす入口。** 起動や投入の手順は、それを持っている文書へつなぐ。書き写すと、手順が
  変わったときに片方だけが古くなる
- **まだ決まっていないこと。** 仮に置いた規則を挙げ、それを管理している場所へつなぐ。どこまでが仮かを
  見せないと、読む人は全部を確定したものとして受け取る。仮置きが無ければこの要素は要らない

## 入力は実装のものを使う

例に使う入力は、実装やテストがすでに使っているものを読み解く。資料のために別の入力を作ると、
実装が確かめている内容と資料が説明する内容が離れる。

判断の規則が現れる入力が足りないと気づいたら、資料の側で補わずに user へ伝える。足すなら実装の側で
足すことになる。

## 説明できなかった箇所を挙げる

書いていて、なぜそう作ったのかが実装からも記録（`JUDGE.md`、PR、Issue など）からも読み取れない
箇所に行き当たったら、資料の中でもっともらしく埋めない。書き終えたときに一覧にして user へ渡す。
埋めた理由はもっともらしく読めるぶん、後から読む人を誤らせる。

## 出力の見た目を残す

画面なら実際に立てて撮り、帳票・ファイル・CLI の出力なら実際に出したものを使う。画像やファイルは
資料と同じ場所に置き、出したときの入力を書き添える。見た目は実装より先に変わるので、撮り直す契機を
資料の側に残しておく。

## このリポでの置き場

当てはまる置き場が無い行は、取り込んだときに消してある。

- 資料と一覧は `<資料の置き場>` に置く。一覧が作成済みと予定の両方を持つ。先に一覧と、書いた例を読む。
  一覧が無ければ `reference/list-template.md` から置く
- 例に使う入力は `<実装とテストが使う入力の置き場>`、動かす手順は `<起動・投入の手順を持つ文書>` にある
- 仮に置いた規則は `<仮置きを管理する場所>` にある
- 画面を撮るときは `<画面を立ち上げる手順>` で一式を立てる
- 書いたら一覧の行を作成済みにし、`<入口の文書>` から辿れるようにする
- 文書だけの変更なので、`docs/ops/branch-and-pr.md` に従って出す
