# qa-collect

依頼主の答えを問いの Issue に写す。答えを写す形の正本は `docs/ops/client.md`「問いの Issue」と `client-next` の
`reference/question-template.md` で、顧客理解担当の仕事は `docs/ops/customer.md` にある。

**写すところで止まる。** 止まる位置は `docs/ops/customer.md`「照会と回収」に従う。

## 1. 答えの出どころを受け取る

照会表・議事録・チャット・資料のどれかを受け取る。パスかリンクが無ければ聞く。原本を実際に読む。

- user が口頭で伝えた答えなら、根拠の場所を聞く。根拠が無ければ「user からの伝聞（<日付>）」と書き、確かめていないことが
  分かるようにする
- 原本がリポジトリの外（`<原本の置き場>`）にあるなら、リンクを控える。原本には顧客の担当者名などの実値が含まれるので、
  ファイルをリポジトリの中に置かない

## 2. 当たる問いを決める

照会表の項目なら、項目に書いた問いの番号で引く。議事録やチャットなら、答えの中身から当たる問いを探し、候補を示す。

```bash
gh issue list --state all --label question --limit 1000 --json number,title,state,body
gh issue view <番号> --comments
```

閉じた問いに当たったら、答えは既に写されている。食い違う新しい答えなら、新しい問いを立てるかを user に聞く。
どの問いにも当たらない答えは、新しい問いの候補として挙げる。

## 3. 写し済みかを突き合わせる

問いごとに、既にある答えのコメントの「- 根拠：」を見る。

| 判定 | 当たるもの | すること |
|---|---|---|
| 写し済み | 同じ原本の同じ箇所を根拠にしたコメントがあり、答えの中身も揃っている | 何もしない |
| 漏れあり | 同じ原本を根拠にしたコメントはあるが、原本の答えの一部がコメントに無い | 抜けた分を補うコメントを新しく書く。既にあるコメントは書き換えない |
| 未写し | その原本を根拠にしたコメントが無い | 4 で写す |

根拠の行だけで判定しない。写し済みでも、答えの本文とコメントを読み比べる。

## 4. 写すものを組む

`client-next` の `reference/question-template.md` の形でコメントを組む。1つの問いに同じ原本から複数の発言があれば、1件にまとめる。

- 答えは言い換えずに写す。原本の言葉が長ければ、問いに答えている部分だけを抜く
- 答えに出てくる人名は書かない。立場に置き換える
- 答えが「判断できない」「〜に確認してほしい」なら、答えは出ていない。そう書いたうえで、`答える人` の付け替えの候補にする
- 既にある答えと食い違えば、どちらを採るかを user に聞く

あわせて、問いの扱いを組む。

| 答え | 扱い |
|---|---|
| 問いに答えが出た | 閉じる |
| 答えが出ていない、または答える人を付け替える | 開いたまま残す。`状態` は `照会中` のまま。付け替えるなら `答える人` を直す |
| 答えが要件の変更に当たり、依頼主の了承がまだ無い | 開いたまま残し、了承を聞く問いを下書きする |

## 5. 一覧を見せて止まる

```
| 問い | 出どころ | 判定 | すること（写す／補う／閉じる／答える人の付け替え／何もしない） |
```

表のあとに、問いごとのコメントの文面、本文の直し、新しい問いの下書きを並べる。顧客名・金額・個人情報の
実値が入っていないかを確かめてから見せる。照会表そのもの（回答欄・状態の列）は直さない。

## 6. 承認を受けて書く

承認を受けたものだけを書く。

```bash
gh issue comment <番号> --body-file <コメント>
gh issue close <番号>                                  # 答えが出た問いだけ
gh issue view <番号> --json body -q .body > <本文>   # 答える人を付け替えるときだけ
gh issue edit <番号> --body-file <本文>
```

`<コメント>` と `<本文>` は一時ディレクトリに置き、リポジトリの中に置かない。

書き終えたら、写した問いを 3 の突き合わせにもう一度かけ、「写し済み」になったことを示す。閉じた問いがあれば、
`client-next` の「答えを回収する」で作業の Issue に反映するよう添えて終える。
