# qa-send

問いの Issue から、依頼主へ送る問いの一覧を作り、照会したことを Issue に残す。答えが戻ってきたら `qa-collect` で写す。
問いの Issue の欄の正本は `docs/ops/client.md`「問いの Issue」で、顧客理解担当の仕事は `docs/ops/customer.md` にある。

写しの側（照会表・打ち合わせの議題）で問いを足したり言い換えたりしない。言い換えたくなったら、先に Issue の本文を直す。

## 1. 送る問いを決める

番号を名指しされたらそれを、答える人の条件ならそれで引く。絞らずに頼まれたら、開いている問いをすべて引く。

```bash
gh issue list --state open --label question --limit 200 --json number,title,body \
  --jq '.[] | (.body | capture("状態: (?<s>[^\n]*)").s // "") as $s
        | (.body | capture("答える人: (?<a>[^\n]*)").a // "") as $a
        | (.body | capture("照会の経路: (?<r>[^\n]*)").r // "") as $r
        | "#\(.number)\t\($s)\t\($a)\t\(.title)\t\($r)"'
```

`状態` の行が無い問いは、欄を足す前の問いである。送らずに挙げ、本文に欄を足すかを user に聞く。

照会中の問いは、前にどこかで聞いている。`gh issue view <番号> --comments` で答えのコメントを読み、送り方を決める。

| 状態 | 送り方 |
|---|---|
| 未照会 | 送る |
| 照会中 | 新しく送らない。照会の経路の回答期限を過ぎていれば督促の候補にする。前の照会に答えが戻っていれば、送らずに `qa-collect` で写す |

## 2. 送る項目を下書きする

問いごとに `gh issue view <番号>` で本文を読み、送る項目を下書きする。

- **1項目は1つの問いにする。** 答える人は本文の `答える人` の1人である
- 中身は本文の `問い` と `選択肢` をそのまま並べる。読み手が背景を知らないと答えられない問いだけ、先頭に1〜2文の前置きを付ける。
  `仮の案` は、依頼主に案として示すと答えやすくなる問いだけに添える
- 顧客名・金額・個人情報の実値を入れない。依頼主へ送る文面でも、Issue に残る文面でもある

照会日は当日、回答期限は照会日から `<回答までの日数>` 後を既定とし、user には聞かない。user が別の日を言ったらそれに従う。
本文の `期限` が回答期限より早ければ、その問いに印を付けて見せる。答えを待つあいだに作業が止まる。

## 3. 一覧を見せて止まる

一覧を「送る」「督促の候補」「送らない」の3つに分け、それぞれを答える人ごとにまとめて見せる。送らない問いには理由を1行添える。

```
| 問い | 答える人 | 中身 |
```

表のあとに、照会日と回答期限を添える。user が一覧を照会表・打ち合わせの議題・チャットへ移して送る。
督促は前の照会の場で行うので、この skill では項目を作らない。

## 4. 送ったあとに Issue を直す

user から送ったと聞いてから、問いごとに本文の2行を直し、直した理由をコメントに残す。

- `状態` を `照会中` にする
- `照会の経路` を `client-next` の `reference/question-template.md` の形で書く。前の経路に残す情報があれば続けて書く

```bash
gh issue view <番号> --json body -q .body > <本文>   # 2行だけを直す
gh issue edit <番号> --body-file <本文>
gh issue comment <番号> --body "<送った場>で <答える人> へ照会したので、状態と照会の経路を直した。"
```

`<本文>` は一時ディレクトリに置き、リポジトリの中に置かない。
