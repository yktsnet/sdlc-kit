この下の区切り線から先が PR 本文の形。`work` が着手前に宣言した対象・完了条件・保証を
そのまま引き継ぎ、`hand-off` が `## 証拠` を足して完成する。

## テンプレから読み取るべきポイント

- **`## 完了条件` は着手前に宣言したものをそのまま置く。** 実装してみて達成できなかった項目を
  黙って書き換えない。変わったなら、変わった旨を書く
- **`## 証拠` は完了条件と1対1で対応させる。** 条件の数だけ証拠がある状態にする。実行した
  コマンドと出力の該当部分を貼り、出力を要約しない
- **実装者側で完結しない確認は `## 検証手順` へ回す。** 証拠の節に「確認済み」と書かない。
  デプロイ後の動作・ブラウザ目視・実機確認がこれに当たる
- **`## 保証` はテストとの対応表である。** 保証の文言だけを並べても、それを固定している
  テストが書かれていなければ約束になっていない。伴わないなら `なし（理由）` と明示する
- 節は該当するものだけ使う。`## 検証手順` が無いなら節ごと消す（「特になし」と書かない）
