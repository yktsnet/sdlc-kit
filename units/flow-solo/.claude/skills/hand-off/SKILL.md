---
name: hand-off
description: work で実装した作業ブランチを、確認者に完了条件を判定させて証拠で裏付けたうえで push し PR を立てる。マージはしない（user が押す）。
---

1人のフローの引き渡し段。**証拠の無い完了を書かない。** 証拠は確認者が取る。

1. `git log main..HEAD` で、`work` が残した完了条件と保証を読み出す
2. 確認者（`completion-verifier`）に完了条件を判定させる。実装者が自分で裏付けない。理由は `docs/ops/workflow.md` の「証拠の無い完了を書かない」にある
   - 渡すのは作業ブランチのチェックアウトのパスだけで、何をどう作ったか・どこを見ればよいかは書かない
   - 「否」があれば PR を立てずに直し、`work` の手順4〜7と同じく確かめてから追加コミットする。そのうえで同じ確認者を再開させ、前回の判定のあとに足したコミットの範囲（`<前回の判定の HEAD>..HEAD`）だけを渡す。何を直したかは書かない。「否」が無くなるまで繰り返す
   - セッションが変わって再開できないとき、または直しが対象の半分以上に触れたときは、新しい確認者で最初から確かめる
   - 「判定できない」は直さず、`## 検証手順` へ回す。ここで「確認済み」と書かない
3. PR 本文を `reference/pr-template.md` に従って組み立てる（節の並び、証拠と完了条件の対応、
   書かないものはここが正）。`## 証拠` には確認者が返した証拠をそのまま貼る
4. 作業ブランチを push し、3 の本文で PR を作成する
5. **マージはしない。** PR の URL と、user が実施する検証手順を報告して終了する

`main` への直接 push とマージは `.claude/settings.json` の deny とフックが遮断する。自分の変更を自分で公開に載せない。
