# rework-review

PR 本文の `## 待ちと手戻り` を集め、繰り返す原因を Issue にする。節の書き方と原因の分類の正本は
`docs/ops/workflow.md`「待ちと手戻りを記録し、仕組みへ返す」で、ここはその手順である。見出しが `## 手戻り` の節も
同じ記録として集める。

相談者として動く。**直さず、PR 本文も書き換えない。** 書き込むのは user が採った候補の起票と、既存の Issue への
追記と、5 のラベル付けだけである。分類の誤りに気づいたら、束ねるときに読み替え、読み替えたことを一覧に書く。

## 1. 待ちと手戻りの節を集める

`rework-read` のラベルが無い、マージ済みの PR を読む。前回読んだ PR にはラベルが付いているので、読み直さずに済む。

```bash
gh pr list --state merged --search "-label:rework-read" --limit 1000 --json number,title,body \
  --jq '.[] | (.body // "" | gsub("\r"; "") | (capture("(?:^|\\n)## (?:待ちと)?手戻り\\n(?<s>.*?)(?:\\n## |\\z)"; "m") // null)) as $c
        | select($c != null) | "### #\(.number) \(.title)\n\($c.s)"'
```

節が `なし` の PR は数えるだけにする。`Closes #` を持つのに節の無い PR は、番号を一覧の最後に添える。番号が多くて一覧が埋まるときは、本数だけを添える。

```bash
gh pr list --state merged --search "-label:rework-read" --limit 1000 --json number,body \
  --jq '.[] | select(.body | test("Closes #")) | select(.body | test("(^|\\n)## (待ちと)?手戻り") | not) | .number'
```

## 2. 束ねて候補を選ぶ

各 PR の待ちと手戻りの表の行を、原因の分類ごとに束ねる。同じ分類の中で「仕組みで防げたか」が同じ欠け（同じ手順・同じスクリプト・
同じフック）を指す行を、同じ原因として1つにまとめる。言い回しが違っても、指す欠けが同じなら同じ原因である。

同じ原因が2本以上の PR に出たものを候補にする。1本の中で続いたやり直しは1回と数える。待ちは同じ工程の待ちが
2本以上の PR に出たら候補にする。失った時間の大小は基準にしない。同じ工程でも、並行させたセッションの数や手元の
負荷で時間が大きく変わるためである。

「実装者の不注意」の行は、`docs/ops/workflow.md` の分類の表にある読み替えに従い、読み替えたものだけを候補にする。

候補ごとに、次を確かめる。

- 直す先がすでに直っていないか。待ちと手戻りを記録した PR のうち一番新しいもののマージより後に、直す先のファイルへ
  入ったコミットを読む（`git log --since="<マージ日時>" --format="%h %cI %s" -- <直す先のファイル>`）
- 同じ主題の Issue が開いていないか（`gh issue list --state open --search "<主な語> in:title,body"`）

## 3. 一覧を見せて止まる

候補ごとに1行で並べ、扱いの案を付ける。

```
| # | 分類 | 原因（1行） | PR の本数 | PR | 案 |
```

案は次の3つのどれかにする。直す先は `docs/ops/workflow.md` の分類の表で引く。直し方は、検査（CI・フック・
スクリプト）にできるなら検査を選ぶ。skill や文書に文を足すと、長くなった分だけ読み落としが増える。

- Issue にする：直す先のファイルと節を添える
- 既存の Issue に追記：手順2で当たった Issue の番号を添える
- 見送る：理由を添える（すでに直った、リポの中では直せない、など）

一覧のあとに、読んだ PR の数・`なし` の PR の数・候補にしなかった行の数と、節の無い PR の番号を添える。
1本だけに出た原因（「実装者の不注意」を除く）も1行ずつ添える。user が選んだ行は候補に加える。

user は候補ごとに案を採るか替えるかを返す。承認を受けるまで起票しない。

## 4. 起票し、追記する

- Issue にする候補は、1件ずつ `issue-draft` の手順で起票する。本文の `根拠` に、待ちと手戻りを記録した PR の番号と行を書く
- 既存の Issue への追記は、追記する文面を見せて OK を受けてから `gh issue comment <番号> --body-file -` で書く

## 5. 読んだ PR にラベルを付ける

1 で読んだ PR すべてに `rework-read` のラベルを付ける。節が `なし` の PR と、節の無い PR も含める。見送った候補は
一覧に残したので、次の回は読み直さない。

```bash
gh pr edit <番号> --add-label rework-read
```

起票した Issue と追記した Issue の番号、見送った候補、ラベルを付けた PR の本数を報告して止まる。
