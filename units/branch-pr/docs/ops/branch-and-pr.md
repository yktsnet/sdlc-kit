# ブランチと PR

ブランチと PR の単位を分けるのは、**戻す範囲を変更1本に閉じるため**である。

## 原則

1. **変更1本ごとに PR を出す。** ブランチの単位＝PR の単位である。GitHub の PR は head
   ブランチと base ブランチで定義されるため、1本のブランチから main 宛の PR を複数は作れない
2. **PR は裁可のあとに出す。** 実装者はコミットで一度止まる
3. **マージは user が行う。** `guards` の deny とフックが `gh pr merge` と main への push を
   遮断する
4. **積むのは依存があるときだけ**

## 何を1本にするか

分ける基準は**戻す単位**に置く。

| 対象 | ブランチ | 1本の単位 |
|---|---|---|
| 完了条件を決めて進める変更 | 作業ブランチ（`flow-issue` なら `claude/{id}-{slug}`、`flow-single` なら `work/{slug}`） | 変更1本 |
| それ以外（その日の文書整備、誤字修正など） | `day/<日付>` | その日の分をまとめて1本 |

前者は1件だけ戻せることに価値がある。後者はまとめても、1件だけ急いで戻す場面が無い。

`day/<日付>` はその日のうちに複数回 switch してよいが、日をまたいで持ち越さない。
**同じ日に無関係な主題が複数あるときは、`day/<日付>-<slug>` のように主題ごとに分ける。**
基準は主題であって日付そのものではなく、日付は「長命にしない」ための上限として使う。

**日付は、コミットした日ではなく作業が属する日を書く。**

## マージ

<CI の有無と、マージ前に何が確かめられるか>

CI が無いリポでは、マージする前に人が読んで判断する。実装者が取った証拠を PR 本文に書き、
マージする時点で同じことを確かめ直さずに済む状態にして渡す。ためらう点が残っているなら、
伏せずに PR 本文へ書く。

承認待ちのブランチは消さない。

## 済んだブランチを片付ける

**ブランチを切る前に main を取り直す。**

```bash
git switch main && git pull
git fetch --prune
git branch --merged main | grep -vE '^\*|^\s*main$' | xargs -r git branch -d
```

`-d` を使う（`-D` ではない）。拒否されたものが出たら、消さずに報告する。

セッション開始時には `.claude/hooks/branch-check.sh` が同じ掃除をし、残った状態を報告する。

**リモートはマージ時に自動で消える。** `.github/workflows/delete-merged-branch.yml` が
`pull_request` の `closed` を受け、マージされた PR の head ブランチを削除する。マージ前に
閉じた PR のブランチは残る。フックがリモートについて報告するのは、このワークフローの
取りこぼしだけになる。

消えて困ることは無い。コミットは main に入っており、GitHub の PR 画面には Restore branch が
残る。

## 積むとき

変更同士に依存があり、片方が main に入るまでもう片方を始められない場合に限り、親ブランチから
切ってよい。積んだ場合は、親ブランチが先にマージされるまで自分の PR を出さないか、base に
親ブランチを指定するかを決める。

## コミットと PR に載せないもの

コミットメッセージと PR 本文は、このリポを触る誰が読んでも通じる状態に保つ。

**開けないリンクを置かない。** 実行環境によっては、末尾に作業ログへのリンクを足すよう
促されることがある。発行元のアカウントでしか開けず、他の担当者が押しても中身に到達できない。

同じ理由で、特定の端末や個人の環境でしか通じない事情も書かない。固有の接続情報（ドメイン
実値・本番の絶対パス・VPN IP・SSH ユーザ名）は `<PLACEHOLDER>` に置き換える。

## 取り込んだあとにやること

1. `.claude/settings.*.snippet.json` をすべて `.claude/settings.json` へマージし、snippet を消す
2. `chmod +x .claude/hooks/branch-check.sh`
3. 「マージ」節の `<...>` を埋める（CI があるか、マージ前に何が確かめられるか）
4. コミットメッセージと PR の言語は `docs/ops/doc-style.md` が正本。ここには書かない
